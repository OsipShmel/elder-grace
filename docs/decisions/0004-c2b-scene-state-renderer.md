# 0004 — Развилка 3: C2-b, нативный рендер по состоянию сцены

Дата: 2026-11-08. Статус: **принято** пользователем.

## Контекст

После фаз 4–5 (путь A, подпроект 1: архивы → текстуры → модели → сцена Stranded Graveyard → сравнение с эталоном по камере из живой игры) стоит развилка 3 из `PLAN.md`: как превращать нативный рендер в играбельный результат.

Цель пользователя: **не** полная замена движка FromSoftware (ИИ, анимации, физика, скрипты — годы), а нативная **графическая** сторона при оригинальной логике игры; в перспективе — инструментарий для переноса частей оригинального бинарника на натив, насколько возможно.

Замеры (`grace-eldenring/docs/BASELINE.md`): узкое место — CPU (главный поток игры под Rosetta + трансляция D3D-вызовов D3DMetal), GPU занят ~67%. Шейдеры игры на GPU уже нативные (D3DMetal → Metal) — подсовывать свои MSL внутрь процесса игры бессмысленно и хрупко.

## Варианты C2

- **C2-a, поток команд:** shim сериализует D3D12-вызовы в наш arm64-процесс, тот исполняет их на Metal (свой D3DMetal). Картинка 1:1 автоматически, общий для любых D3D12-игр; но это полная реализация D3D12 + передача гигабайт ресурсов между процессами.
- **C2-b, состояние сцены:** shim/инструменты достают из живой игры **смысл** (камера, объекты и их трансформы, анимация, свет, время суток, эффекты), наш процесс сам грузит меши/текстуры/материалы из файлов игры (слой данных) и рисует своим рендером.

## Решение

**C2-b.** Рендер полностью наш: можно быстрее и лучше оригинала (MetalFX, ProMotion, свои освещение/апскейл), ресурсы не гоняются между процессами, и всё уже сделанное ложится прямо: слой данных (`er-data`), сцена из MSB, `grace-render`, камера из живой игры, автоматическое сравнение с эталоном (M6). Отложенный выигрыш: когда наш рендер рисует кадр, игру можно лишить рендера (не исполнять её отрисовку) — уходит работа D3DMetal и часть нагрузки главного потока.

## Последствия

- Нужен разбор памяти игры для динамического состояния (персонажи, позы, эффекты, интерфейс) — это знание об Elden Ring, живёт в `grace-eldenring`; ядро даёт общие примитивы (поиск структур по самопроверяемым сигнатурам, `FindFloats`, `Peek`, каналы shim ↔ рантайм).
- Версия игры важна (структуры памяти): сейчас 1.17.2 (приложение) / 1.17.3 (калибровки).
- Интерфейс (HUD/меню) — отдельное решение: пропускать проход UI игры поверх нашего кадра или переделывать.
- Перенос частей бинарника на натив — дальняя цель; физика (arm64 и x86_64 не смешиваются в процессе) оставляет путь «целые подсистемы в нашем нативном процессе» или статическую перекомпиляцию exe целиком; наш C2-b-процесс станет их «хостом».
- Вехи C2-b — в `PLAN.md` («Фаза 6 — C2-b»), перед ними — реструктуризация репозиториев (ADR 0005, «Фаза R»).
